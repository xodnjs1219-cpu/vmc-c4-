## 실시간 채팅 서비스 기능 단위 유저플로우 (최종본)

### 유저플로우 1: 신규 사용자 회원가입

#### 1. 입력 (Input)
-   사용자가 회원가입 페이지에 접근한다.
-   닉네임, 이메일, 비밀번호, 비밀번호 확인 필드에 값을 입력한다.
-   회원가입 버튼을 클릭한다.

#### 2. 처리 (Processing)
1.  시스템은 제출된 폼 데이터의 유효성을 검사한다.
    -   **[Edge Case]** 필수 입력 필드가 비어있는지 확인한다.
    -   입력된 이메일 주소 형식이 올바른지 확인한다.
    -   입력된 닉네임이 시스템에 이미 존재하는지 데이터베이스를 조회하여 확인한다.
    -   입력된 이메일이 시스템에 이미 존재하는지 데이터베이스를 조회하여 확인한다.
    -   **[Edge Case]** 비밀번호가 정책(8자 이상)을 만족하는지 확인한다.
    -   **[Edge Case]** 비밀번호와 비밀번호 확인 값이 일치하는지 확인한다.
2.  모든 유효성 검사를 통과하면, 시스템은 비밀번호를 안전한 방식으로 해싱(hashing)하여 암호화한다.
3.  시스템은 사용자가 입력한 닉네임, 이메일, 그리고 암호화된 비밀번호를 새로운 사용자 계정으로 데이터베이스에 저장한다.

#### 3. 출력 (Output)
-   **유효성 검사 실패 시:** 각 실패 원인에 해당하는 피드백을 사용자에게 표시하고, 비밀번호를 제외한 기존 입력 값은 유지한다.
-   **회원가입 성공 시:** 회원가입 완료 피드백을 잠시 표시한 후, 사용자를 로그인 페이지로 리디렉션 시킨다.
-   **[Side Effect]** 시스템 데이터베이스에 새로운 사용자 정보가 영구적으로 기록된다.

### 유저플로우 2: 사용자 로그인

#### 1. 입력 (Input)
-   사용자가 로그인 페이지에 접근한다.
-   이메일, 비밀번호 필드에 값을 입력한다.
-   로그인 버튼을 클릭한다.
-   **[Edge Case]** '비밀번호 찾기' 링크를 클릭한다.

#### 2. 처리 (Processing)
1.  시스템은 제출된 데이터의 유효성(필드 공백 여부)을 검사한다.
2.  입력된 이메일로 데이터베이스에서 사용자를 조회한다.
    -   **[Edge Case]** 해당 이메일의 사용자가 없으면 로그인 실패로 처리한다.
3.  입력된 비밀번호를 해싱하여 데이터베이스의 비밀번호와 비교한다.
    -   **[Edge Case]** 비밀번호가 일치하지 않으면 로그인 실패로 처리한다.
4.  인증 성공 시, 사용자의 세션 또는 토큰을 생성한다.
5.  '비밀번호 찾기' 클릭 시, 해당 페이지로 이동을 처리한다.

#### 3. 출력 (Output)
-   **로그인 실패 시:** 통합된 로그인 실패 피드백을 표시한다.
-   **로그인 성공 시:** 사용자를 홈(채팅방 목록) 페이지로 리디렉션 시킨다.
-   **[Side Effect]** 브라우저에 인증 정보(세션/토큰)가 저장된다.
-   **'비밀번호 찾기' 클릭 시:** 비밀번호 찾기 페이지로 리디렉션 시킨다.

### 유저플로우 3: 새 채팅방 만들기

#### 1. 입력 (Input)
-   사용자가 홈 페이지에서 '새 채팅방 만들기' 버튼을 클릭한다.
-   채팅방 이름 입력 필드에 값을 입력하고 '만들기' 버튼을 클릭한다.

#### 2. 처리 (Processing)
1.  시스템은 제출된 채팅방 이름의 유효성을 검사한다.
    -   **[Edge Case]** 이름이 비어있는지 확인한다.
    -   **[Edge Case]** 이름이 최대 길이(100자)를 초과하는지 확인한다.
    -   **[Edge Case]** 동일한 이름의 채팅방이 데이터베이스에 이미 존재하는지 조회하여 확인한다. (중복 불허)
2.  유효성 검사를 통과하면, 채팅방 이름과 개설자(현재 사용자) 정보를 데이터베이스에 생성하고 고유 ID를 부여한다.

#### 3. 출력 (Output)
-   **유효성 검사 실패 시:** 실패 원인에 대한 피드백을 표시하고 입력 값은 유지한다.
-   **생성 성공 시:** 사용자를 새로 생성된 채팅방 페이지(`/room/[newRoomId]`)로 리디렉션 시킨다.
-   **[Side Effect]** 홈 목록에 새 채팅방이 즉시 표시되며, 데이터베이스에 채팅방 정보가 영구 기록된다.

### 유저플로우 4: 채팅방 목록 확인 및 입장

#### 1. 입력 (Input)
-   사용자가 홈 페이지에 접근한다.
-   표시된 채팅방 목록에서 특정 채팅방을 클릭한다.

#### 2. 처리 (Processing)
1.  시스템은 홈 페이지 접근 시 사용자의 인증 상태를 확인한다.
    -   **[Edge Case]** 미인증 사용자는 로그인 페이지로 보낸다.
2.  인증된 사용자에게 데이터베이스의 모든 채팅방 목록을 조회하여 제공한다.
3.  사용자가 특정 채팅방 클릭 시, 해당 채팅방의 고유 ID(`roomId`)가 유효한지 확인한다.

#### 3. 출력 (Output)
-   **인증 실패 시:** 로그인 페이지로 리디렉션 시킨다.
-   **홈 페이지 접근 성공 시:** 전체 채팅방 목록을 화면에 표시한다. (방이 없으면 비어있다는 피드백 표시)
-   **채팅방 입장 실패 시 (유효하지 않은 방):** 홈에 머무르며 유효하지 않은 방이라는 피드백을 표시한다.
-   **채팅방 입장 성공 시:** 해당 채팅방 페이지(`/room/[roomId]`)로 리디렉션 시킨다.

### 유저플로우 5: 실시간 메시지 전송

#### 1. 입력 (Input)
-   사용자가 채팅방에서 메시지 입력창에 텍스트 또는 이모티콘을 입력한다.
-   전송 버튼을 클릭하거나 'Enter' 키를 누른다.

#### 2. 처리 (Processing)
1.  시스템은 메시지 내용의 유효성(공백 여부, 최대 길이 등)을 검사한다.
2.  유효성 검사를 통과하면, 메시지 정보(내용, 작성자, 타임스탬프 등)를 데이터베이스에 저장한다.
3.  시스템은 실시간 통신 채널을 통해 해당 채팅방의 모든 사용자에게 새 메시지 데이터를 전달(broadcast)한다.

#### 3. 출력 (Output)
-   **유효성 검사 실패 시:** 전송되지 않으며, 실패 피드백을 표시하고 입력 내용은 유지된다.
-   **전송 성공 시:** 채팅방의 모든 사용자 타임라인에 새 메시지가 즉시 추가되고, 보낸 사람의 입력창은 초기화된다.
-   **[Side Effect]** 전송된 메시지는 데이터베이스에 영구적으로 기록된다.

### 유저플로우 6: 메시지 상호작용 (좋아요, 답장, 삭제)

#### 1. 입력 (Input)
-   사용자가 특정 메시지에서 상호작용 메뉴('좋아요', '답장', '삭제')를 활성화하고 클릭한다.
-   '삭제'는 자신이 작성한 메시지에만 노출된다.

#### 2. 처리 (Processing)
1.  **'좋아요' 클릭 시:** '좋아요' 추가/취소 로직을 수행하고 데이터베이스에 기록한 뒤, 실시간으로 모든 사용자에게 상태 변경을 알린다.
2.  **'답장' 클릭 및 전송 시:** 원본 메시지 ID와 함께 답장 메시지를 데이터베이스에 저장하고, 실시간으로 모든 사용자에게 전달한다.
3.  **'내 메시지 삭제' 클릭 시:**
    -   메시지 작성자와 현재 사용자가 일치하는지 확인한다.
    -   데이터베이스에서 해당 메시지를 '삭제됨' 상태로 변경(update)한다. (물리적 삭제 아님)
    -   실시간 통신 채널을 통해 모든 사용자에게 해당 메시지 ID가 삭제되었음을 알린다.

#### 3. 출력 (Output)
-   **'좋아요' 성공 시:** 모든 사용자의 화면에서 해당 메시지의 '좋아요' 상태 및 카운트가 실시간으로 업데이트된다.
-   **'답장' 성공 시:** 모든 사용자의 타임라인에 원본을 인용한 답장 메시지가 나타난다.
-   **'삭제' 성공 시:**
    -   **[타임라인]** 모든 사용자의 메시지 타임라인에서 해당 메시지가 즉시 사라진다.
    -   **[답글 내 표시] [Edge Case]** 삭제된 메시지에 대한 기존 답글이 있었다면, 그 답글들 내부에서 인용되던 원본 메시지 내용이 **"삭제된 메시지입니다."** 텍스트로 대체된다.

### 유저플로우 7: 마이페이지 정보 확인 및 닉네임 수정

#### 1. 입력 (Input)
-   사용자가 마이페이지로 이동하여 '수정' 버튼을 누른다.
-   새로운 닉네임을 입력하고 '저장' 또는 '취소' 버튼을 클릭한다.

#### 2. 처리 (Processing)
1.  시스템은 마이페이지 접근 시 사용자의 현재 정보를 데이터베이스에서 조회한다.
2.  '저장' 클릭 시, 입력된 새 닉네임의 유효성을 검사한다.
    -   **[Edge Case]** 닉네임 공백 여부, 현재 닉네임과 동일 여부, 다른 사용자와의 중복 여부를 확인한다.
3.  유효성 검사를 통과하면, 데이터베이스의 사용자 닉네임 정보를 업데이트한다.
4.  '취소' 클릭 시, 변경 사항을 저장하지 않고 이전 상태로 되돌린다.

#### 3. 출력 (Output)
-   **마이페이지 진입 시:** 사용자의 가입 정보(이메일, 닉네임, 가입일)를 표시한다.
-   **유효성 검사 실패 시:** 실패 원인에 대한 피드백을 표시한다.
-   **닉네임 수정 성공 시:** 수정 완료 피드백을 표시하고, 화면에 업데이트된 새 닉네임을 보여준다.
-   **[Side Effect]** 서비스의 모든 부분(채팅방, 메시지 등)에 변경된 닉네임이 즉시 적용된다.
